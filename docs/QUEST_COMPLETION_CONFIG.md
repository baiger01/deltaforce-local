# 任务完成配置

配置文件：`outputs/df-local-server/config/quest_completion.json`。
服务创建 Backend 时读取，修改后重新启动服务或原客户端测试程序生效。
也可以通过本地服务的 `--quest-completion-config <文件>` 指定其它配置文件。

默认关闭：

```json
{
  "enabled": false,
  "complete_all": false,
  "complete_quest_ids": []
}
```

一键完成当前已恢复目录中的全部 2365 条任务：

```json
{
  "enabled": true,
  "complete_all": true,
  "complete_quest_ids": []
}
```

只完成指定任务，例如原客户端的任务 11001 和 21001：

```json
{
  "enabled": true,
  "complete_all": false,
  "complete_quest_ids": [11001, 21001]
}
```

任务 ID 来自 `protocol/native_quest_catalog.json` 的 `quests[].QuestID`，
目标和数量来自 `protocol/native_quest_objectives.json`，支持目录内逐条选择。
未知 ID、重复 ID、错误字段和错误类型会在服务初始化时明确报错，不会静默忽略。
全部任务包括目录中的历史和特殊任务，不等于只完成当前赛季的部门任务。

## 生效和存档

- 开启后，在已登录账号请求任务列表时，整批写入该账号的原生任务存档。
- 将目标置为完成并填入原表要求的数量，任务状态保存为 `Completed`。
- 不自动领取奖励、不扣提交材料、不改变声望或部门等级。`Rewarded` 保持独立。
- 已完成和已领奖的任务不重写；重复请求不会重复生成任务或发奖。
- 整批事务失败时回滚，也不发送成功通知；成功后按原协议同步任务通知。
- 最初状态保存在 `native_lobby_quest_completion_overrides`，便于核查配置产生的进度。
- 修改开关为关闭，不撤销已经保存的完成状态。关闭时不会再新增完成进度。
- 配置对使用它的 Backend 生效；每个账号仅在自己读取任务时应用，写入按账号隔离。

当前提交的配置保持关闭，没有对现有测试账号执行全任务完成。
上述目录不包括由其它系统独立维护的通行证或活动任务。

## 部门恢复的边界

完成开关已接入任务服务及通知。配置只标记完成，用户点击领取时仍走独立领奖事务。
普通 Mission/Branch 的简单物品提交、钱包余额条件，以及已验证奖励类型的落库已接入；
实际库存、绑定状态、所需数量、重复领取和事务回滚都有校验。
奖励枪使用原始预设的完整配件树，经验与部门声望分别保存到账和奖励收据。
复杂提交条件、特殊任务类型，以及尚无唯一部门来源的奖励不会用猜测关系发放。

普通手动任务支持放弃：进度清空后回到未接受状态，已提交材料不返还；
重新接受仍检查当前等级、任务线、已领奖前置与冷却。自动接受及特殊任务另走原生专用流程。
开启完成配置后，已保存的 Completed 不会被普通放弃接口撤销。

原表 Type2 Currency 的五档现金目标是余额条件，不能通过物品提交扣款。
接受和查询时读取实际哈夫币余额；其它交易成功后也刷新已接受现金任务并发通知。
不创建实体现金道具，不把余额再次作为提交消耗。完成状态保留与其它任务一致，
这是明确的本地判定策略，未声称恢复官方远端的完成锁定代码。

设施升级使用 `native_safehouse_catalog.json` 原始条件：行动等级、前置设施、部门声望、
任务、材料和货币分别检查，升级倒计时期间不提前获得目标等级的功能。
例如仓库八级原表要求行动 42 级、设施 1002 达到 3 级、战术声望 3 级，
这些条件全部满足才允许开工；完成配置不代替这些检查，也不自动升级设施。

声望累计值独立保存，等级查询、领奖通知和设施声望要求共用
`protocol/native_reputation_curve.json` 的 20/30/30、终点 4 级。
第一档来自原始服务提供者明确列出的进度要求，第二、三档有原版进度界面证据；
这是注明来源限制的本地重建，未恢复官方服务端配置或第一档原版进度弹窗。
终点档分数未知并省略，不填一个虚构的终点分数。

任务的行动经验使用原 SeasonLevel 60 级表更新行动等级、级内经验和通知，
仓库等设施随即读取该等级检查前提。账号与爆破等级不由行动任务经验推高。
旧档没有历史行动经验明细时，以原存等级下限建立明确审计的本地基线，
不追认历史经验；旧账号、爆破展示值另存基线，经验与阈值暂保留原本地零值。
