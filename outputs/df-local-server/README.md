## 运行

**使用独立前端入口：双击 `open-local-entrance.cmd`，或打开 `http://127.0.0.1:8877/`。** 启动脚本会启动本项目服务；如果同版本服务已运行，会复用它。此入口无需 WeGame 或官方账号，所有页面资源都在本地。选择“注册新账号”，填写自己的用户名、至少 8 个字符的密码和确认密码。已有本地账号可以直接登录。

登录后可查看总览，在仓库与背包之间移动物品、拆分堆叠和装备武器，在任务页领取、提交物品、完成及领取奖励。数据自动保存；浏览器刷新后需要重新登录。当前物品和任务为自建开发数据；战斗事件任务尚不能在页面中完成。浏览器入口仍不能启动原游戏大厅；原客户端大厅目前通过单独的本机诊断测试接通，尚未整合为稳定的用户启动流程。

脚本使用 PATH 中的 Python；前端启动日志位于 `data/entrance-server.log`。需要在终端运行或观察日志时，执行 `python -m dfserver.entrance --no-browser`；关闭该服务终端可以停止由它启动的服务。端口被其他服务占用时不会终止对方，可用 `--port` 指定另一端口。

需要 Python 3.10 或更高版本。业务核心只使用标准库。运行全套测试需要安装 `requirements-optional.txt` 中的依赖。

在本目录运行：

```text
python -m dfserver
```

也可以双击 `start.cmd`。开发接口监听 `127.0.0.1:8877`，保存文件位于 `data/local.sqlite3`。可用 `--port`、`--database` 和 `--definitions` 参数更改端口、存档和数据定义；`--game-port` 指定区服发现应答中的本机游戏端口，默认 65010。

接入诊断可运行 `python -m dfserver.connection_probe` 或 `probe-connection.cmd`，默认监听 `127.0.0.1:65010`。它只检查首包并将字段类型、大小和结果写入 `data/local-connection-probe.json`，不会发送握手 ACK 或登录应答，也不能进入大厅。原始包、密钥和凭据不会写入报告。已有探针运行时应复用它；同一端口不能重复启动。

`python -m dfserver.handshake_diagnostic --modulus-file 私有参数文件` 是本机握手诊断端的常规模式：仅在提供**已验证的客户端 64 字节 DH 公共模数**后生成 ACK。另有 `--diagnostic-exponent-one` 模式，使用只适合回环诊断的公开会话值，无需模数；2026-09-28 原客户端实测已据此发送下一条传输认证请求。这个模式**不能保护账号会话**，不得作为最终网关或对外监听服务。命令行模式只记录命令和字段长度，不发送账号授权或游戏登录应答；受控测试助手可选择发送零值的协议解析探针，这不构成账号授权。运行前须先停止占用 65010 端口的首帧探针；本次实机诊断已结束，监听已停止。

账号与存档保存在同一 SQLite 数据库。密码保存为随机盐和 PBKDF2-HMAC-SHA256 校验值，会话保存摘要。改密会撤销该账号全部旧会话。旧版仅凭角色名登录的入口已取消；旧开发存档保留，旧无密码会话失效，不能通过注册直接领取旧角色。

## 开发接口

业务接口采用本项目自有开发协议。区服发现接口采用公开应答的字段格式；原客户端兼容性仍未验证。

| 接口 | 用途 |
| --- | --- |
| `GET /`、`GET /ui/` | 独立本地入口；静态资源仅开放指定 HTML、CSS、JS 文件 |
| `GET /healthz` | 运行状态 |
| `GET /api/status` | 已实现操作与协议缺口 |
| `GET /api/local/catalog` | 本地物品与容器定义；不包含账号或存档 |
| `POST /api/local/register` | 请求 `username` 和 `password`，创建独立账号及存档并获得本地会话 |
| `POST /api/local/login` | 请求 `username` 和 `password`，校验本地密码后获得会话 |
| `POST /api/local/logout` | 请求 `{}` 并提供 Bearer 会话，注销该会话 |
| `POST /api/local/change-password` | 请求 `current_password` 和 `new_password` 并提供 Bearer 会话，改密并返回替代会话 |
| `POST /api/local/dispatch` | 调用下表中的业务操作，需要 `Authorization: Bearer <本地会话>` |
| `POST /api/local/native-identity` | 请求 `{}` 并提供本地 Bearer 会话；返回自有 DFID 二进制身份格式，供原生提供者读取 |
| `POST /api/protobuf/decode` | 按已恢复的描述符解码 `message` 与 `payload_base64` |
| `POST /api/protobuf/dispatch` | 当前返回 `GAME_GATEWAY_NOT_READY`；原客户端诊断连接另走临时网关，尚未在此 HTTP 接口启用原游戏业务协议 |
| `POST /api/v1/wegame.rail.game.RepoSVC/GetZone` | 接收 `game_id=2001918` 与 `from_src=launcher`，返回仅包含本机地址的区服发现配置 |

业务请求示例：

```json
{
  "operation": "quests.accept",
  "payload": {"quest_id": "local_supply"},
  "request_id": "accept-1",
  "expected_revision": 0
}
```

读操作无需 `request_id` 和 `expected_revision`。写操作必须提供二者；发生 `STALE_REVISION` 后应重新读取大厅状态。重试同一请求应使用原请求 ID、原参数和原版本，返回原响应；同一请求 ID 不能用于另一项操作。

| 操作 | 参数 |
| --- | --- |
| `profile.get`、`hall.get`、`inventory.list`、`quests.list` | 无 |
| `inventory.move` | `instance_id`、`container`、`x`、`y`、可选 `rotated` |
| `inventory.split` | 与 move 相同，加 `quantity` |
| `inventory.equip` | `instance_id`、`slot` |
| `quests.accept`、`quests.complete`、`quests.claim`、`quests.abandon` | `quest_id` |
| `quests.submit` | `quest_id`、`objective_index`、`instance_id`、`quantity` |

`Backend.record_event()` 是供本地战斗实现调用的受信接口。当前没有战斗模拟器；测试中的事件由测试程序产生。

## 采集真实网关报文

当前 Codex 会话调用 Pktmon 驱动返回“拒绝访问”。需要手动右键 `capture-gateway.cmd`，选择“以管理员身份运行”。它使用 Windows 自带的 [Pktmon](https://learn.microsoft.com/en-us/windows-server/administration/windows-commands/pktmon)，不安装驱动，不修改或注入游戏，也不自动申请提权。

脚本默认采集 60 秒，必须先保持原游戏运行。它查询 TCP 连接所属进程并核对安装路径，为该客户端当前的每条 IPv4 TCP 连接设置 IP 和双方端口筛选器，包含本机代理连接，并在整个网络栈采集。采集范围不会扩展到共享代理的其他应用连接。它检查已有采集与过滤器，结束时停止本次采集并删除本次添加的过滤器。预检查已改为 `pktmon status`，避免 `logman` 的 WMI 查询错误；命令输出采用 UTF-8 优先解码，避免中文乱码。

第一次按历史网关地址采集 180 秒，管理员采集与导出流程成功，但 PCAPNG 中没有数据包。第二次采用客户端连接模式，取得 11,381 个数据包记录。导出的接口标记为以太网，但其中包含 6,844 个原始 Wi-Fi 帧；解析器已补上对应识别规则，恢复出 12 个 TCP 数据方向，包括大厅网关的双向连接。

在大厅右键以管理员身份运行 `capture-gateway.cmd`，看到 `Capturing ...` 后，移动一次仓库物品，再打开任务页面。ETL、PCAPNG 和采集记录保存于 `data/captures/`，不进入源码压缩包。

**采集登录握手使用 `capture-login.cmd`。** 先保持游戏关闭，右键脚本以管理员身份运行，看到 `Capturing ...` 后，再通过 WeGame 正常登录大厅，等待 180 秒结束。当前登录采集筛选 TCP 的源端口或目标端口 `65010`，不固定网关 IP，以覆盖客户端通过自身解析器选择的新地址。它不会扩展到本机代理端口 `7897`，但可能包含其他程序在同一 `65010` 端口上的流量，分析时仍需确认 GCP 包头和连接归属。`--use-capture-gateways` 保留为按此前有效采集的具体 IP 筛选的可选模式。

请保持脚本窗口打开直到导出完成。提前结束时使用 Ctrl+C，可保存已经采到的数据。直接关闭窗口可能让 Windows 的 Pktmon 会话继续运行；此时再次以管理员身份运行 `capture-login.cmd`，它会验证日志路径位于本项目的采集目录、所有筛选器属于该会话、原脚本进程已经退出，再停止这个残留会话并导出原 ETL。这次恢复完成后直接返回，不会立即开始新的采集。仍有原采集进程、其他筛选器或归属无法确认时，会保留正在运行的会话。

采集完成后运行：

```text
python tools/analyze_capture.py data/captures/实际文件名.pcapng
```

分析器重组 TCP 数据，报告缺口、重传冲突、已知消息名和路由字段候选；默认结果不包含账号字段值或 IP 地址。独立实现的 `dfserver/gcp_framing.py` 已恢复 `0x3366` 包头、版本、命令、加密标记以及头部和正文长度。真实大厅采集中的 36 段连续数据共 120 个包，均按七字节分段读入并逐字节重新编码验证成功，详见 `protocol/gcp_framing_validation.json`。实际版本为 11，命令包括 `0x4013` 和 `0x9001`。这些命令是传输层命令，不能当作仓库或任务的业务消息 ID。

2026-09-27 的登录采集取得 3,355 条数据包记录，包含同一连接的 `0x1001` 请求和 `0x1002` 应答。独立解析器对连续数据中的 494 个完整 GCP 包按七字节读入，并验证重新编码一致。客户端方向的 46 段连续数据均完整；服务端方向仍有 12 处不完整尾部和 20 处无法从包边界开始的片段，没有拼接缺失数据，不能称为全流验证。详情见 `protocol/login_transport_validation.json`。

静态调用和实际握手确认 key mode 3 使用 Diffie–Hellman，生成元为 2，共享值按不补零的大端形式计算 MD5 后作为 AES-128-CBC 密钥，正文使用自定义 `tsf4g` 尾部。`dfserver/gcp_crypto.py` 已独立实现这一算法；`dfserver/gcp_handshake.py` 已解析观察到的公钥和压缩参数。客户端发包依据会话方法加密，即使包头加密标志为零也不能当作明文；服务端发包的解密受该标志控制。

握手中公钥后面的固定 64 字节在此前采集中全为零，保留为未解释字段，不能当作 DH 模数。客户端预置的公共模数仍未恢复。2026-09-28 原客户端已向本机探针发送完整的 `0x1001` 首帧；随后另一轮诊断发送 ACK 并收到认证请求。正式账号授权仍未验证。ACK 正文的字段布局及传输认证请求、应答编解码已实现，但上下文、部分整数和账号授权仍未确认。已有抓包没有客户端或服务器的私有指数，因此尚未解密官方会话。仓库与任务的业务绑定尚未启用。

随后多次独立原客户端测试使用仅监听回环地址的临时诊断端：它发送长度和包头与官方采集相符的 `0x1002` ACK，原客户端随即发送 `0x2001` 传输认证请求。诊断端成功解码请求布局，只保存认证类型 `4096`、凭据 5 字节、附加认证数据 96 字节、上下文 0 字节等元数据；没有保存字段内容、会话值或原始包。第二轮还在内存中比对当前本地账号会话，确认认证请求字段包含自建的本地会话令牌；没有保存令牌、摘要、会话值或原始包。该诊断会话值公开可算，监听已停止，不能将其用于实际账号授权。每轮结束后原 SDK 已恢复，已发送的零值解析探针尚未获得客户端认证成功；游戏登录及大厅仍未完成。完整边界见 `protocol/current_handshake_progress.json`。

后续确认原客户端当前登录流使用 `0x3366` 帧，先前调查的 `0xaa` 内层格式属于另一条 `0x4366` 路径。原客户端的 `0x2002`、`0x6002` 读取器均能完整解析本项目构造的最小固定字段应答。实机单发 `0x2002` 时客户端重试并报连接超时（内部错误 3）；紧接着发 `0x6002` 时客户端立即报 GCP 错误 203。仅证明正文解析器接受结构，不证明完整帧、状态转换或账号授权成功。两次尝试验证分开发送的后续 Windows 授权均返回 1223，游戏未启动，原文件没有被替换。协议证据见 `protocol/auth_response_parser_evidence.json`。

已进一步检查四个可执行文件中的连续十六进制候选，以及三份资源包内 16,708 个哈希校验通过的明文条目；候选值没有通过基本素数筛查。加密或超限条目、运行时生成或分段保存的参数不在本次范围内，不能据此认定参数不存在。上层配置传入 `TPInitInfo` 的路径见 `protocol/dh_parameter_provenance.json`，当前握手里程碑见 `protocol/current_handshake_progress.json`，官方 ACK 包头元数据见 `protocol/handshake_header_words.json`。
